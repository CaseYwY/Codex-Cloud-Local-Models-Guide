# 接入全过程与方案演进

以下按原机记录整理。记录中的成功只适用于当时的版本、账号和配置；目标机要重新验收。

|阶段|做了什么|发现与后续决定|
|---|---|---|
|本地服务基础|先通过自定义 runtime 将 NInfer 接入 llama.cpp Windows Manager，验证认证、文本和流式响应|原版 Manager 的 runtime 与模型登记限制不能通过改文件扩展名绕过，采用适配层|
|预算适配|定义敏思 16K、穷理 32K，Responses 请求里映射真实模型名、thinking_budget 与 max_output_tokens|保留 input、tools 和工具输出历史；目录描述本身不会改变推理参数|
|独立 CLI profile|保留本地 CLI 入口，云端仍作为全局默认|CLI 成功不能证明桌面共用菜单成功|
|错误的桌面切换|最近模型/桌面别名继续使用 openai provider|原机复现本地别名被 ChatGPT provider 拒绝，不能把模型别名当作 provider 切换|
|统一回环网关|建立 cloud-local-router，云端和本地统一经过网关再分流|正式云端认证保留；本地分支剥离云端认证，改用本地认证|
|完整目录|保留官方云端模型及完整元数据，追加本地条目|只写两个本地模型的目录会替换云端目录，缺少元数据还会影响思考强度与能力|
|真实双路验收|云端、敏思、穷理分别回复，同聊天切换并读随机文件|证明指定版本上的请求与工具循环；没有因此宣称所有 MCP、图像、语音都通过|
|退出后空白菜单|网关依附启动进程，退出应用后没有服务|改用独立普通用户计划任务和 supervisor，避免随一次命令结束|
|离线菜单修复|启动时目录仍依赖服务在线|设置完整本地 model_catalog_json；后台更新采用原子替换，刷新失败保留旧文件|
|自动恢复|增加登录与每分钟触发，恢复整个网关退出|这属于旧生命周期方案，后来被随应用启停取代|
|黑色 PowerShell 窗口|任务直接启动 powershell，即使 WindowStyle Hidden 仍出现 Terminal|改用 GUI 子系统启动器，在创建进程时 CreateNoWindow 并重定向输入输出|
|一次流式断开|在活动聊天期间停止共享路由以测试恢复|约 3.4 秒后恢复，但既有连接已中断；随后两次真实流式回复完整通过。正式故障测试必须避开活动推理|
|随桌面应用启停|不希望登录后一直常驻路由|新增 AppModel 激活事件控制器，最后一个应用进程退出 15 秒后停止；去掉旧登录/分钟触发与 Startup 启动项|

## 最终保留的设计

统一 provider、原账号云端认证、完整本地目录、NInfer 请求预算映射、后台 supervisor、无窗口进程创建、按桌面应用生命周期启停。

原机当前可见目录记录为 7 个云端加 2 个本地。目录中的隐藏条目也保留，不能通过“只复制这 7 个名字”推广到其他账号。

## 不应复用的历史结论或做法

- “本地只能用于 CLI，不能加入桌面菜单”已被统一路由的实测取代。
- 全局切到仅本地 provider，或把全局目录改成只有本地条目，不满足保留云端模型的目标。
- 仅凭 `/v1/models` 或独立 App Server 成功，就宣布桌面界面、退出重开和所有工具可用，证据不足。
- 每分钟拉起与应用退出停止同时存在，会相互抵消。采用当前方案时必须移除旧触发器。
- 通过正在工作的同一个网关做“结束所有服务再等恢复”的验收，会打断聊天，不能作为日常健康检查。

## 历史验证边界

随应用启停的临时任务五项行为已通过，应用激活事件筛选已对真实日志核对。部署当时完整退出并重开正式桌面应用的验证被自动审批以 `blocked by policy` 拒绝，因此该项保留为未完成验证。本次整理没有重启应用来补测，也没有将它改写为已通过。

原机 Manager 早期文档中的 8K、200K 配方是历史阶段。Codex 本地目录后来声明 256K；新设备不得将旧参数表与新目录混合使用，更不能仅凭目录字段宣布实际上下文能力。
