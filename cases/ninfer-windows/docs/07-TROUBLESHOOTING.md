# 故障处理

先确认失败发生在目录、网关、云端、本地服务、协议还是后台生命周期。收集必要的状态与脱敏错误，避免用全局重装掩盖原因。

|现象|先检查|处理|
|---|---|---|
|云端模型消失|全局model_catalog_json指向什么，是否只有本地两条|重新生成完整官方目录加本地条目，不手写云端型号|
|菜单空白|本地目录文件是否存在，schema与引擎是否匹配|离线可读的完整目录；配置/目录变更后重开客户端|
|推理强度消失|是否只保留了slug和display_name|保留官方完整元数据，本地字段按后端与客户端schema核对|
|本地别名报not supported when using Codex with a ChatGPT account|实际provider是否仍openai|使用已验证统一provider，不能仅修改最近模型名字|
|连接127.0.0.1:18767失败|网关任务和监听进程，应用生命周期是否运行|启动自有任务并检查日志；当前全局provider仍依赖它|
|本地不可用|本地服务监听与认证、真实Responses路径|启动目标机已有服务或修复其配置，云端不需要因此切换|
|401|返回者是路由还是本地服务|分别核对路由密钥和模型密钥，绝不打印值|
|403 browser_origin_not_allowed|是否用普通网页跨源调用本机网关|保留网关边界，从原生Codex客户端测试|
|终端关掉又开|任务是否直接运行PowerShell、是否还有旧分钟/登录触发|无控制台GUI启动器；当前方案清理自己的旧触发器|
|桌面退了但网关一直在|是否还有Codex应用进程、是否旧Startup或分钟任务仍在|以最后一个真实应用进程及15秒宽限判定，不按单窗口判定|
|从任务栏启动没路由|AppModel日志、事件ID与ApplicationName是否匹配|核对本机安装方式，验证真实事件；必要时适配启动集成|
|CLI使用中网关停止|桌面应用已经完全退出|当前生命周期只看桌面；CLI采用独立直连profile或另设计生命周期|
|thinking_budget报错|是否误传0、字段是否为后端实际支持名|关闭思考使用后端支持的关闭方式，不以0伪装；核对原生日志|
|工具不执行或丢失上下文|tools schema、call_id、function_call_output、input是否被修改|检查真实请求和重放，保留原始参数，不能删除工具来绕过|
|只有HTTP 200随后报流断开|网关是否重启，SSE是否完整，上游代理是否断开|按下面顺序定位，不批量改网络设置|

## stream disconnected / error decoding response body

该错误说明响应流未完整收到，不足以单独断言模型格式错误或模型安装失败。

1. 先对照出错时间与gateway/supervisor/lifecycle进程更换记录。路由重启会打断已有流，服务恢复不等于旧响应能够续传。
2. 若PID稳定，再检查云端上游、系统代理、HTTP内容编码和SSE终止事件。本地转发若解压请求，必须移除content-encoding并重算content-length；云端原始转发则保留对应编码关系。
3. 不重启共享服务，发送两次可控的真实请求，确认文本增量与最终completed、无error事件。
4. 仅在当前请求已结束后重试必要输入。不要自动重放包含有副作用工具的整个回合，避免重复执行。

原机03:11的事件与主动故障测试停止网关吻合，约3.4秒后服务恢复；之后两次真实流式回复完成。它不是持续网络故障已被证明的案例，目标机应依据自己的时间与日志判断。

## 代理与更新

参考refresh-proxy.ps1在启动时读取Windows系统HTTP代理写入私有settings.json。代理改变后要在空闲时重新加载网关，不能为刷新设置打断活动聊天。Node版本不支持参考proxyEnv行为时，先修复该兼容层并实测云端，不关闭证书校验来凑连接成功。

Codex更新后默认模型、目录schema、应用进程名或包激活方式可能变化。重新核对而不是恢复一份旧的全局配置。无需为了使用本方案修改Codex应用二进制或迁移到Ollama。
