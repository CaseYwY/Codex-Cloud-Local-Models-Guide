# 回退和移除

回退目标是恢复目标设备原有云端使用，同时保留安装后用户做的无关修改。旧整份config.toml备份用于比对，不应默认覆盖当前文件。

## 恢复云端直连

1. 在当前配置中只撤销本方案的顶层model_provider选择，恢复安装前的有效云端provider或内置openai。
2. 若model_catalog_json恰好指向本方案生成的完整缓存，移除本方案选择并恢复先前目录设置。不是本方案的路径不得删除。
3. 默认model恢复目标机安装前的云端默认；不能写死原机的gpt-6.1-sol。
4. 保留其他provider表、MCP、apps、插件、权限和后续修改。未选中的路由provider可暂留，不影响直连。
5. 写前备份当前文件，解析TOML并核对差异，写回后读回确认。auth.json不变。
6. 等活动任务完成后重开Codex，用真实云端回复确认已经直连。

## 然后清理后台

**先恢复并验证云端直连，再停止仍承载请求的网关。** 当前provider仍指向网关时先停它，会让云端同样离线。

停用并移除自己创建的Codex Router App Lifecycle和Codex Cloud Local Router任务，检查本方案自己的Startup快捷方式与桌面快捷方式。如果任务在安装前就存在，按备份恢复而不是直接删除。

清理残留Node进程时，按当前会话、完整脚本参数和运行目录精确匹配，先停止supervisor再停止gateway。不要使用按名称结束全部node/powershell/ChatGPT进程的命令。删除运行目录前解析绝对路径，确认只在本方案目录内，保留需要的私有备份。

Manager和本地模型独立管理。仅撤销Codex路由不需要卸载模型、不需要重置Manager，更不需要编辑它的SQLite。若安装中修改过本地适配层，应在目标服务空闲、具备适用授权后按其单独备份回退。

## 只回退后台机制

若仅将“随桌面启停”退回“独立常驻”，恢复本设备安装前保存的任务定义与自己的快捷方式，并再次核对不会同时存在相反的触发机制。此操作不应改模型、认证或请求预算。

原机restore-cloud.py含原机默认型号与目录假设，因此没有把它当作通用回退器分发。其他设备应据本设备备份生成最小逆向修改。
