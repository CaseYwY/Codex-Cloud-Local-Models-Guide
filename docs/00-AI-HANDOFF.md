# AI 执行入口

## 目标

在当前设备的 Codex 中保留已有云端模型和默认选择，接入一个或多个本地模型。后端、模型、部署位置和推理控制均由设备现状与用户选择决定。用户提及的 slang 在本文按推理框架 SGLang 理解。

## 执行顺序

1. 读取当前设备与仓库 AGENTS.md，盘点客户端版本、实际配置目录、云端默认及认证方式。
2. 识别已有本地服务，记录推理引擎、版本、运行位置、模型 ID、端口、认证及管理方式。不要求重装已有可用服务。
3. 根据 [后端适配矩阵](10-BACKEND-COMPATIBILITY.md) 探测 Responses、流式、工具和历史能力。
4. 根据 [推理与参数](11-REASONING-AND-PARAMETERS.md) 确认每个模型支持的控制；未知保留未知，未支持的控制不要暴露到菜单。
5. 先准备目标机路由/能力清单，再实现或复用路由和必要兼容层。`examples/routes.example.json` 是设计模板，不是可直接运行的网关配置。
6. 备份原配置，添加未选中的候选 provider，在隔离进程验证。不要先把当前聊天切到未验证网关。
7. 保留完整云端元数据，按目标客户端 schema 添加实际本地模型。别名和原云端 ID 不能冲突。
8. 按 [通用安装流程](03-INSTALL.md) 最小部署，分别管理网关和后端生命周期。
9. 按 [验收清单](06-VERIFICATION.md) 检查每个模型、工具、认证与用户宣告的推理选项。
10. 填写 [设备报告](../examples/installation-report.md)，写明已验证、失败、未验证和回退方法。

## 完成条件

云端原有功能保留；所有交付的本地模型按其声明能力完成真实请求；目录与路由一致；不存在未声明的参数覆盖或静默模型替换；配置和服务可回退。没有推理强度设置的模型，不要求出现强度菜单才能算完成。

如果后端只会返回文本、工具链路仍失败，只能报告文本接入通过，不能报告完整 Agent 接入成功。没有可运行的模型或必要协议时，保留原云端正常使用，并说明剩余条件。

## 可转发指令

```text
在本设备按仓库通用流程接入 Codex 本地模型，同时保留原云端模型、登录和默认值。
先读 AGENTS.md、docs/00-AI-HANDOFF.md、docs/03-INSTALL.md。
后端可能是 vLLM、SGLang 或其他服务；模型、数量和参数不预设。
先盘点后端版本、实际 API、模型及能力，再决定直连转发还是协议兼容层。
不要照搬 NInfer 案例的别名、预算、推理强度、端口或硬件配置。
不支持推理控制的模型不要强加控制；支持的选项逐项映射、逐项实测。
先备份和隔离验证，再最小部署。不打断共享服务，不泄漏云端认证。
最后按 examples/installation-report.md 报告真实结果和未验证项。
```
