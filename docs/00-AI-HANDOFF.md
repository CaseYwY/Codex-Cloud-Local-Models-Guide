# AI 执行入口

## 任务目标

在当前设备的 Codex 桌面版中，保留用户现有云端模型和云端默认，增加本地模型选择。可采用原机的敏思 16K、穷理 32K 两个别名，但必须确认目标后端能执行这些预算。不得把请求静默切换至另一个模型。

本仓库是一个已验证方案的安装说明和源码快照。执行者需要为目标设备生成配置、补齐本地认证接入和目录，不应向用户声称 clone 后就已经装好。

## 执行顺序

1. 按 [03](03-WINDOWS-INSTALL.md) 盘点 Windows、Codex 桌面内置引擎、Node、现有云端默认、模型目录、本地服务与端口。填 `examples/device-inventory.example.json` 的本地副本。
2. 读取 [01](01-ARCHITECTURE.md) 和 [02](02-HISTORY.md)，理解为什么使用统一 provider，以及旧方案在哪些环节失败。
3. 若本地 Responses 服务不存在，先按 [04](04-LOCAL-RESPONSES.md) 建立并独立验证它。原机自定义 Manager 适配层不是原版 Manager 的开箱能力。
4. 备份目标设备配置和将修改的自有脚本。生成独立路由密钥，准备部署目录。
5. 检查 `reference/README.md` 的机器绑定项。复制允许分发的源码到私有运行目录，再适配目标路径、版本、端口与本地认证来源。
6. 使用目标设备自己的账号，在单独 app-server 进程里覆盖 provider 参数进行测试。暂不切换正在运行的 Codex 全局路由。
7. 按 [05](05-CATALOG.md) 获取该设备实际云端完整目录，追加本地条目。文件存在、可解析且包含全部云端元数据后，才配置 `model_catalog_json`。
8. 完成云端与本地真实回复、同聊天模型切换、工具读文件和认证隔离验收。
9. 编译无窗口启动器，安装随桌面应用启停的两个任务。完成临时生命周期测试；安排空闲窗口重开桌面应用，确认界面菜单。
10. 按 [06](06-VERIFICATION.md) 提交逐项报告。失败则按 [07](07-TROUBLESHOOTING.md) 定位，必要时按 [08](08-ROLLBACK.md) 回退。

## 完成条件

云端默认保留，云端与本地都真实完成回复；目录保留云端能力元数据；本地服务关闭时云端仍可用；菜单在路由离线时仍可读取；工具历史没有被删除；后台不弹终端；没有停止无关模型或改写登录文件。

至少一项未达到时，报告明确写部分完成和具体阻碍。原机的成功记录不能作为目标设备成功的证据。没有合适 GPU、模型文件或兼容 Responses 后端时，先保留原云端正常使用，不得伪造本地安装成功。

## 发给两位 AI 的完整指令

```text
请在这台设备安装“Codex 保留云端并接入本地模型”。
先读仓库 AGENTS.md、docs/00-AI-HANDOFF.md、docs/03-WINDOWS-INSTALL.md。
你负责本设备的完整安装，不操作另一台设备。
保留现有云端默认、全部云端模型及 MCP/apps/插件等无关设置。
使用本设备自己的登录和密钥；不要照搬原机目录、端口或模型参数。
先盘点与备份，再用隔离进程验证，随后部署。
按 reference/README.md 核对源码中的机器绑定项。
网关不得暴露到局域网，不得把云端认证转发给本地模型。
正在进行推理时不重启共享网关。正式生命周期测试安排在空闲窗口。
最后用 examples/installation-report.md 的本地副本报告真实证据、失败和未验证项。
```

如果接收方运行 macOS、Linux、WSL 或未打包的 Codex，应复用协议与目录设计，重新实现启动层；本仓库的 Windows AppModel 任务不能直接应用。
