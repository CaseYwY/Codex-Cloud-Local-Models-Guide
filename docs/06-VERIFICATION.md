# 安装验收

每台设备分别记录版本、操作、时间、实际结果和脱敏证据。以下不是原机结果的复制表。对于会影响活动服务的步骤，先使用独立临时任务，正式测试安排在空闲窗口。

|检查|执行方式|通过证据|
|---|---|---|
|配置保护|前后解析TOML，对比预期变更，比较登录文件本地哈希|无关配置保留，auth.json未改动|
|真实云端|目标设备自己的正式登录，经候选provider发Responses请求|文本增量到达，最终completed，内容符合提示|
|两个本地档位|分别用本地别名请求|本地模型真实回复，预算与输出上限有有效值证据|
|本地工具|临时只读目录写随机标记文件，让本地模型用工具读取|真实commandExecution退出0，工具结果含标记，最终回复一致|
|同聊天切换|GPT→敏思→穷理→GPT，续问刚读出的标记|每次指定模型完成，后续仍有正确历史|
|认证隔离|用一次性伪造云端认证标记测试本地分支，不输出真实认证|本地正确认证成功，云端标记不传给本地；错误本地认证被拒绝|
|网关权限|无路由密钥、错误路由密钥、浏览器Origin|分别401/401/403；健康检查仍可用|
|本地离线|本地服务本来就未运行，或用户选定空闲窗口停止它|云端继续成功；本地明确失败，不悄悄转云端|
|离线目录|隔离进程在网关不可达时读取本地完整目录|全部云端+本地条目及推理强度仍在|
|桌面菜单|实际重开目标桌面应用并观察菜单|云端默认、各模型和强度均显示|
|无终端窗口|启动和恢复后观察真实可见窗口|没有本方案造成的Terminal/PowerShell窗口|
|临时生命周期|使用独立任务测试启动、故障恢复、退出停止等|五项完成，正式服务不受影响|
|正式生命周期|空闲窗口完整退出和重开桌面，测试快捷方式和原生入口|应用开时路由在，最后进程退后按期停止，无分钟触发重新拉起|
|更新与回退|核对源哈希、配置备份、回退步骤|可恢复原云端，后续用户设置不被旧整份备份覆盖|

## App Server观测要点

使用目标设备桌面实际内置引擎，通过stdio JSONL初始化、thread/start和turn/start驱动真实模型。临时thread使用ephemeral，并在可控的只读fixture中测试工具。

收集item/agentMessage/delta、item/completed、turn/completed及error事件。最终turn.status必须为completed。仅收到文本增量、进程退出0或HTTP 200都不充分。请求不含工具时不要宣称工具闭环已经验证。

原机已有verify.py等脚本使用私有配置路径和固定exe，不直接分发为通用安装脚本。执行者应按目标版本的app-server协议生成自己的验收驱动，不复制登录状态。

## 现成只读和临时检查

参考 `verify-background-window.ps1 -Seconds 90 -AssertNoWindow` 只观察，不重启生产路由。该脚本采用原机端口18767，且会统计所有可见WindowsTerminal/PowerShell窗口；有用户自己打开的终端时要人工区分，不能误杀窗口以通过检查。

`verify-lifecycle.ps1` 使用独立临时任务和模拟客户端验证控制器五项行为，结束时清理自己创建的任务与进程。必须先核对部署路径并编译组件。它证明控制器逻辑，不证明真实Codex包激活事件、所有启动入口或正式应用完全退出场景。

正式进程结束会破坏正在进行的SSE。原机曾为故障恢复验证停止共享网关，导致用户收到stream disconnected。安装验收不应再次复现这一操作事故。

## 长期使用边界

额外测试长对话/compact、图像、语音、MCP、apps、插件和不同GPT型号时逐项记录，不从一次文本测试外推。新客户端升级后重新检查schema、目录和provider特性。

最终填写 [报告模板](../examples/installation-report.md)。状态只用通过、失败、未验证、不适用，并写明不适用的理由。
