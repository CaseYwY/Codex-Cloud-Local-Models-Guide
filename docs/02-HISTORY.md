# 从原机案例到通用流程

初版交接围绕一台 Windows 设备的 NInfer 接入，包含特定模型、两个预算别名和后台脚本。用户明确要求本地服务不限于该后端、模型和推理配置，因此当前版本把这些固定条件移出主流程。

|保留为通用原则|只属于历史案例|
|---|---|
|保留云端默认和完整目录|某个云端型号及固定模型数量|
|验证实际 Responses、流式、工具和历史|某个引擎版本、端口与 runtime 路径|
|每个模型按实际能力声明参数|特定模型别名、强度和 token 预算|
|认证隔离、最小变更与回退|OpenCode 本地密钥读取和特定 Manager 集成|
|避免窗口与活动连接被后台操作打断|Windows AppModel 事件及进程名称|

完整原机过程、源码和脱敏证据保存在 [NInfer Windows 案例](../cases/ninfer-windows/README.md)。其事实和源码哈希保留，不将历史成功扩展为其他后端的安装结果。

当前主流程新增了后端能力矩阵、协议选择、动态模型和推理配置，以及无推理控制模型的验收分支。仓库提供实施要求和模板，实际部署由目标设备的 AI 根据该设备证据完成。

本次通用化没有重新配置原机模型或网关，也没有安装 vLLM、SGLang 或其他运行时。
