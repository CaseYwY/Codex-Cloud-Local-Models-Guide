# 通用故障排查

先确定错误属于客户端配置、目录、模型路由、协议、参数、认证、网络还是服务生命周期。记录目标版本与脱敏错误，不以重装全套服务作为第一步。

|现象|核对|处理方向|
|---|---|---|
|云端模型丢失|自定义目录是否只剩本地条目|恢复完整云端元数据，再追加本地|
|未知模型/路由错误|客户端 alias、目录 slug、实际 served model ID|修正明确映射，不能静默转云端|
|本地模型仍发到原云端|实际生效 provider 与路由选择|模型名不等于 provider 切换，核对客户端实际请求|
|Chat 成功但 Codex 失败|真实 API 与 Responses 契约|探测原生 Responses，或验证完整兼容层|
|有文本但工具失败|工具 parser、schema、call_id、输出与历史|保真转换，不删 tools 或历史|
|强度选项报参数错误|该模型/版本是否支持字段和值|修正该模型能力表及映射，不套其他模型设置|
|非推理模型出现强度菜单|本地目录是否复制了其他模型元数据|按客户端 schema 取消虚假控制，核对实际界面|
|参数看似可选但无效果|服务端是否忽略、模板是否接受、优先级|观察有效参数，不能只看请求被接受|
|上下文或输出越界|实际模型、启动参数和目录声明|以实际能力和硬件限制修正声明|
|401/403|哪个层返回，认证是否串用|分别核对网关、云端与本地，避免输出令牌|
|找不到服务|容器/WSL/宿主地址、监听、代理和健康|从 Codex 所在环境验证可达，不猜 localhost|
|关闭窗口影响其他任务|网关/后端是否被共享|按实际客户端范围管理，不只看单窗口|
|意外弹终端|平台启动方式是否创建控制台|修正进程创建机制，Windows 细节参考案例|

## stream disconnected / error decoding response body

该错误表示未完整接收或解码响应，不直接证明模型配置错误。先对照时间检查网关、兼容层与后端是否重启，以及代理和内容编码是否一致。

若进程稳定，检查 SSE 增量和终止事件、上游网络、代理缓冲、Content-Encoding、Content-Length 与异常返回。Chat 到 Responses 转换时还要检查事件格式，不能把任意文本包装成合法事件。

修复后在不重启共享服务的条件下验证真实流式完成。不要自动重放含副作用工具的整回合；服务恢复不等于被中断的请求可以继续。

原机案例曾因主动终止网关而打断活动连接。那是生命周期测试造成的中断，不能据此把其他设备上的同名错误也归为同一原因。

## 升级后不兼容

客户端、引擎、模型、parser 或 chat template 任一升级都可能改变能力。保留版本记录，重验实际使用的协议与参数。推理 parser、工具 parser 与模型模板应匹配，不通过统一启用最高强度或固定预算来掩盖不兼容。

未知时保留原云端路径并报告缺口，避免将不支持字段静默删除后声称配置完全生效。
