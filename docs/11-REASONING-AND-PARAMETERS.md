# 推理控制与模型参数

没有统一适用于所有本地模型的推理强度或预算。要区分客户端控件、协议字段、后端实现、模型能力和部署默认值，并确认它们的优先级。

## 能力状态

|实际情况|目录与界面|请求处理|
|---|---|---|
|不支持推理控制|不宣告虚假强度；按客户端 schema 表示无控制|不注入不支持字段；对未知显式控制清楚报错|
|只有模型默认|显示受支持的默认/无控制状态|保持默认，不自动加预算或强度|
|支持离散强度|仅提供已验证的级别|按该模型的实际协议和值映射|
|支持思考开关|只提供能真实启停的选项|使用目标模型与模板支持的开关，不能猜 0 或 none 的含义|
|支持数值预算|说明范围、单位和有效性证据|仅在支持时发送预算；不把总输出上限当作思考预算|
|支持预设|声明每个 preset 的真实参数组合|可选别名或界面策略；不要求每个模型都创建预设|
|尚未确认|不把未知能力交付为可选项|先探测，不用案例值填空|

客户端的 none、low、medium、high、xhigh 等字符串不是后端通用枚举。前端选项只能来自目标版本 schema 与模型实测映射，不能默认列满，也不能一律映射到同一个最高强度。

## 映射的四项证据

1. 该模型和引擎版本的文档定义了什么字段、值和边界。
2. 实际请求到达目标后端时携带了什么，兼容层改了什么。
3. 服务端解析后的有效值是什么，有没有被启动默认、模板或其他参数覆盖。
4. 客户端显示的选项和输出行为是否符合这份声明。

缺少有效值证据时写明限制。模型愿意输出更长的文字、请求未报错或出现 reasoning_content，都不单独证明强度或预算生效。推理 parser 用于解释输出格式，不能据其开启就断言可控制推理量。

## 默认值与优先级

分别记录模型默认、服务启动默认、路由 preset、用户单次请求和兼容转换的优先级。目标后端怎样裁决以其实际行为为准。冲突项优先清楚拒绝，不静默覆盖用户选择。

本地规则仅作用于选中的本地路由。云端已有推理控制原样保留；切换模型时不遗留另一个模型的设置。

## 其他参数同样动态

上下文与输出不能仅按模型名称猜测，部署上下文可能小于权重标称长度。采样、chat template、工具 parser、量化、并行和硬件配置也分别记录，不将通用接入文档变成统一性能配方。

思考预算若存在，不等于总输出上限；控制 token、实际 reasoning token 与最终文本也可能计量不同。没有数值预算能力时不为了生成两档菜单而捏造预算。

使用 [路由模板](../examples/routes.example.json) 的未知值表示未验证，完成后在设备私有副本记录实际映射。NInfer 案例只展示一种已发生的映射，不能把其模型和数值推广到 vLLM、SGLang 或其他服务。
