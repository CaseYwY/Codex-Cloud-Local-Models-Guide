# 通用回退

回退以目标设备安装前状态和实际变更清单为准，不预设云端型号、后端或目录。旧整份配置用于比对，不默认覆盖用户后续无关修改。

1. 备份当前状态，只撤销本次新增的全局 provider/模型/目录选择，恢复原云端有效配置和默认。
2. 若当前目录属于本次生成的混合目录，恢复原目录来源。其他目录、认证、工具、插件和权限不动。
3. 解析配置，核对最小逆向差异，写回读回。登录文件保持不变。
4. 在活动任务结束后重新加载客户端，通过真实云端请求确认已恢复原连接路径。
5. 确认当前客户端不再依赖新增网关后，才停用其自有后台组件。
6. 自己新建的服务定义、任务、快捷方式按平台方式撤销；安装前存在的则恢复原定义，不直接删除。
7. 推理服务、模型文件、驱动和共享后端独立处理，撤销 Codex 接入通常不需要卸载它们。

清理进程按完整运行目录、参数、会话或服务身份匹配，不按 node/python/powershell 等通用名字批量结束。递归删除或移动前核对绝对路径，范围仅限明确属于本次安装的目录。

若只是回退一个模型的参数映射，修改该路由与目录条目即可，不重置所有模型。新模型和其他后端的请求不能被旧案例规则覆盖。

回退脚本由目标设备根据自身备份生成，并记录在 [设备报告](../examples/installation-report.md)。原机案例中的固定回退器不作为通用工具运行。
